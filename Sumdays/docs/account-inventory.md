# 계정별 로컬 보관함

여우, 장식 재고, 포인트, 보유 테마, 적용한 테마·여우, 합성 중 예약 재고는 로그인한 사용자의 ID별로 저장한다. 로그인하지 않은 상태는 별도의 `guest` 보관함을 사용한다. 로그아웃하거나 다른 계정으로 로그인해도 원래 보관함은 남으며, 같은 계정으로 돌아오면 다시 불러온다.

## 저장과 화면 전환

- `AccountStorage`: SharedPreferences 이름 뒤에 `__user_<id>` 또는 `__guest`를 붙인다. 합성 이미지는 `app_fox_previews__<account>` 디렉터리에 저장한다.
- `AccountInventory`: 세션 변경 시 이전 계정의 메모리 캐시와 선택 목록을 비우고 새 계정의 소유 정보와 여우를 불러온다.
- `InventoryOwner`: 화면 및 팝업을 처음 연 계정을 저장한다. 계정 변경 후 도착한 구매, 삭제, 합성 저장, 팝업 닫힘 콜백은 새 계정 데이터를 수정하지 않는다. 화면 재생성에도 원래 계정을 유지한다.
- 합성 재료는 선택 시 예약 차감한다. 편집 화면 재생성은 예약을 이어받고, 취소 또는 새 합성 세션 시작은 해당 계정의 예약만 한 번 반환한다. 완성은 추가 차감 없이 예약을 확정한다.
- 모든 이미지 읽기·삭제는 현재 계정의 실제 저장 디렉터리 안에 있는 파일에만 적용한다. 여우 ID가 같아도 계정이 다르면 이미지 파일은 다르다.
- 상점은 다시 표시될 때 잔액과 재고를 갱신하고, 구매 직전에 저장된 잔액을 다시 읽는다.

이 변경의 범위는 이 기기의 로컬 보관함이다. 다른 기기로 보관함을 옮기는 서버 동기화는 포함하지 않는다. 일기·메모·문체·주간 통계의 Room DB와 기존 동기화 흐름은 별개다.

## 이전 버전의 공용 보관함

공용 저장 파일은 지정된 소유자에게 한 번 옮긴다. 이 프로젝트의 기존 기기 데이터는 사용자 지시에 따라 **로그인 ID `Meow`(사용자 ID `20`, 표시 닉네임 `Meown`)**의 보관함으로 복구했다. 원본 파일도 그대로 보존한다. 다른 기기에 남은 공용 데이터를 옮길 때는 소유자를 확인한 뒤 저장소 루트의 `tools/migrate_local_inventory.py`를 사용한다. 앱이 임의로 현재 로그인한 계정에 원본을 복사하지는 않는다.

이 도구는 디버그 앱과 adb가 필요하다. `--serial`, `--owner-id`, 새 `--backup-dir`를 명시하면 먼저 변경 없는 사전 확인을 수행한다. `--apply`를 추가하면 앱을 종료하고 원본 및 대상의 기존 빈 설정 파일을 백업한 뒤 해당 계정의 저장 공간으로 복사한다. 앱 실행으로 생긴 빈 설정 파일은 허용하지만, 실제 데이터나 이미지가 있는 대상 계정은 덮어쓰지 않는다. PNG는 Windows에서도 바이트가 변하지 않도록 Base64로 전송하고, 임시 파일의 내용을 검증한 뒤 이름을 바꾼다. 원본 PNG가 없으면 누락을 숨기지 않고 중단한다.

기기의 `files/legacy_inventory_assignment.json`에 소유자와 완료 상태를 기록하여 다른 계정으로 중복 복사되는 것을 막는다. 전송이 중단됐으면 원본과 백업을 유지한 채 중단 기록을 남긴다. 기록을 지우고 재실행하지 말고 백업·기기 파일의 해시와 소유자를 대조해 복구해야 한다.

Meow 복구 결과: 기존 여우 4개(`angry`, `happy`, `magician`, `cool`), 합성 PNG 2개, 장식 8개(재고 키 10개), 5,300포인트, 적용 여우 `cool`을 복원했다. `Medium_Phone` 에뮬레이터의 실제 앱에서 원본·다른 계정·인증 정보 보존 및 복원 파일 7개의 바이트 일치를 확인했다. 백업과 검증 기록은 저장소 루트의 `local-backups/meow-inventory-20261010/`에 있으며 Git에서 제외된다.

앱 재실행 후 옷장에서 `magician`·`cool` 및 합성 이미지, `cool` 적용 표시를 확인했고 상점에서 `5,300`포인트 표시를 확인했다. 복구 도구 회귀 테스트 6개도 통과했다.

## 검증

복구 도구의 빈 대상 처리, 기존 데이터 보호, 이미지 경로 변환, 바이너리 전송, 백업 및 중복 이관 차단은 저장소 루트에서 검증한다:

```powershell
python -m unittest discover -s tools -p 'test_migrate_local_inventory.py' -v
```

`Sumdays` 디렉터리에서 실행:

```powershell
.\gradlew.bat -I gradle/fox-placement-tests.init.gradle :app:assembleDebug :app:testDebugUnitTest --console=plain
```

이 명령은 계정·로그인·여우 편집 회귀 테스트를 함께 컴파일하고 실행한다. 기존 전체 테스트에 남아 있는 다른 기능의 컴파일 오류와 분리한 실행 경로다. A→B→A 전환, 게스트 복원, 계정별 PNG, 예약 반환, 이전 계정 팝업의 지연 콜백, 상점 갱신, 로그인 정보 저장 실패 및 기존 배치·표정 편집을 검증한다.

실제 Android 키스토어·파일 저장소 및 Activity 전환은 연결된 에뮬레이터에서 별도로 검증한다:

```powershell
.\gradlew.bat -I gradle/inventory-device-tests.init.gradle :app:connectedDebugAndroidTest --console=plain
```

이 실행은 `com.example.first.inventorycheck`라는 별도 앱과 전용 테스트 러너를 사용한다. 사용자의 `com.example.first` 앱 데이터는 건드리지 않으며, 테스트 중 일기 샘플 삽입과 서버 백업 작업을 실행하지 않는다. 일반 기기 테스트 명령에서는 이 전용 테스트 3개를 건너뛰므로 실사용 보관함에 테스트 계정을 쓰지 않는다.

전용 실행 이후 기본 패키지 APK가 필요하면 init 스크립트 없이 `:app:assembleDebug`를 실행한다. 검증 결과: 로컬 회귀 테스트 38개와 Android 16 기기 테스트 3개 통과. 전용 테스트 러너 없이 일반 `MyApplication`으로 시작해 로그인 화면까지 진입하고, 해당 프로세스의 크래시 로그가 없는 것도 확인했다. 기본 `com.example.first` 패키지 APK도 다시 빌드했다.
